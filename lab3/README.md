# ЛР3, вариант 1

C++17 и Go 1.22+. Полное бинарное дерево (вариант 3 ЛР1), линейное
пробирование и двойное хеширование со свёрткой (вариант 1 ЛР2).

От ЛР1 сохранены массив с удвоением буфера и сдвигом элементов, узлы
односвязного и двусвязного списков, FIFO/LIFO и заполнение дерева по уровням.
В ЛР3 эти алгоритмы адаптированы к общему интерфейсу контейнеров и хранению строк.

## C++ в Ubuntu

Пакеты для сборки и проверок: `build-essential cmake libboost-dev libgtest-dev
gcovr python3 clang-tidy`. Команды выполняются из каталога с этим Makefile:

```sh
make demo
make test
make coverage
xdg-open coverage/cpp/index.html
make benchmark
make lint
```

Обычная сборка тестов включает doctest, Boost.Test и GoogleTest. Режим CMake
`LAB3_CORE_ONLY=ON` оставляет только встроенный doctest для ограниченной среды.
Цель `make coverage` также запускает демо и бенчмарк, чтобы измерить их
исходники. Код тестов и сторонние заголовки не входят в оценку покрытия.

## Go

Нужен Go SDK. При первом запуске тестов Go скачает testify и его зависимости.
Для `make -C go lint` дополнительно нужен golangci-lint v2.

```sh
make -C go demo
make -C go test
make -C go coverage
xdg-open go/coverage.html
make -C go benchmark
make -C go lint
```

Обе цели покрытия отдельно проверяют каждый файл с исполняемым кодом:
результат ровно 85% считается недостаточным. Go-файл `container.go`
содержит только объявления интерфейсов, поэтому у него нет процента покрытия.
Исходники UML: `uml/classes.puml`, `uml/go_types.puml`.

## Что проверено при подготовке архива

Сборка напрямую через g++: демо и бенчмарк запустились, doctest —
31 сценарий, 375 проверок. Фактическое построчное покрытие g++/gcov
доступно в `reports/cpp-coverage-verified.html` (doctest + демо + бенчмарк).
Полный запуск CMake с Boost.Test и GoogleTest, прогон линтеров и измерение
Go требуют соответствующих инструментов; их результаты в архиве не заявлены.
